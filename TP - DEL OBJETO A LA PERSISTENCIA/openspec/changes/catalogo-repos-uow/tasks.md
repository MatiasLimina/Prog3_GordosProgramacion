# Tasks

Strict TDD: cada comportamiento tiene una tarea RED (test que falla, ejecutado, con el motivo de la falla anotado) antes de su GREEN (mínimo código, tests ejecutados en verde). Los tests con base llevan `pytestmark = pytest.mark.db` y se corren con `REQUIRE_TEST_DB=1`. Se entrega en dos PRs (design D10): grupos 2–7 = PR 1 (libros y punto único de stock, fila `en curso`); grupos 8–11 = PR 2 (editoriales, géneros y autores; fila `mergeado (#N)`, Transición y archivo). Commits: uno por módulo, p. ej. `refactor(libros): repositorio con borrado lógico, UoW y punto único de stock`; los ajustes mecánicos de tests existentes van en commits `test(...)` propios. La sesión de ADMIN en los tests se arma con `entrar_como(client, sessionmaker_test, "ADMIN")` de `tests/auxiliares_auth.py` (CHG-12), que devuelve el `usuario_id`; no se agregan fixtures a `tests/conftest.py`.
