# Tasks

Strict TDD: cada comportamiento tiene una tarea RED (test que falla, ejecutado, con el motivo de la falla anotado) antes de su GREEN (mínimo código, tests ejecutados en verde). Los tests con base llevan `pytestmark = pytest.mark.db` y se corren con `REQUIRE_TEST_DB=1`. Un solo PR. Las sesiones de los tests HTTP salen de `entrar_como(client, sessionmaker_test, "<ROL>")` y de `insertar_usuario` de `tests/auxiliares_auth.py`; no se agregan fixtures a `tests/conftest.py`. Las tareas asumen las opciones recomendadas de Q1–Q6 (design, «Decisiones a confirmar»); si 1.3 elige otra, se ajustan las tareas marcadas con (Qn) antes de seguir. Commits: `feat(ventas): registro atómico con stock y aviso en segundo plano` para el código; los ajustes de tests existentes en commits `test(ventas): ...` propios.
